# Word 批注与基础校对

默认交付带真实Word批注的DOCX。原稿另存副本，保留正文文字、原有批注、引用、图表和格式；修改方案写在批注中。用户另行要求修订痕迹或改后净稿时再生成，不以净稿替代批注稿。PDF来稿需先说明转成Word后的版式限制；不能把普通彩色文字或页尾意见列表称作Word批注。

## 两类批注

**论证角色批注**贴在有关句段上，标明主张、理由、证据、根据、承认、回应中的实际功能，带稳定关系ID，例如“[角色 C2 主张]”“[角色 E3 证据→R1→C2]”。必要时同一段一条批注列出各句功能，或同一句注明不同层级的双重功能。背景、定义、方法操作和转场可标其实际功能，不硬塞论证标签。

- 主张：作者希望读者接受的结论，区分全文、节和局部层级。
- 理由：为什么接受某主张；继续追问可形成下一级主张。
- 证据：为理由或主张提供支持的观测、资料、引文、结果；引文不是自动可靠的证据。
- 根据：从理由/证据到主张必须接受的一般联系。隐含根据在批注标为“重建，需作者确认”，不能插入原文伪装成作者已说。
- 承认：公平呈现与自身主张有关的限制、异议或竞争解释；“虽然”不自动构成实质承认。
- 回应：说明承认内容如何影响主张、如何以材料回应或如何收窄主张；不要把结尾再次断言标成有效回应。

全稿逐段检查角色，功能明确者做角色批注；纯公式、参考文献等无需逐项强贴标签。总论证图可在首个中心主张批注中说明关系ID。缺失要素在最近相关主张处标“未见明确表述/当前范围待核”，不在正文造句，也不在每段凑齐六类。

**修改意见批注**锚定最小足够范围。每条使用以下内容，长短随问题复杂度调整：

```
[A012｜主要｜推理：因果越界｜已确认/风险/待核]
关联角色：E3 → C2
问题：该观察只能支持什么，原句却推出什么。
原因：缺了哪条支持关系，为什么会改变结论或读者理解。
修改建议：现有材料能完成的最小修法。
建议句：忠实于已有材料的完整替代表述；无可靠替代句则说明待补信息。
如保留强主张：需要新增何种证据/分析；不能把待补结果写进建议句。
依据：相关图表、稿内位置、期刊卡ID/教材规则ID；无依据不编造。
```

角色批注是描述，不自动代表有错误；修改建议区分纠错、风格可选项和需作者研究判断的事项。已正确处不制造错误。不同问题可分别批注，同一断点多处出现时用关系ID交叉引用，避免大量重复。

## 校对范围与轻重

| 类型 | 检查对象 | 处理方式 |
|---|---|---|
| 科学含义 | 因果/关联、范围、量词、指标、单位、分母、数据与图表冲突 | 优先批注，解释会改变哪个结论；事实未核不猜正确值 |
| 论证 | 证据不足、不当类比、根据不成立、循环论证、非相干结论、逻辑跳步、竞争解释遗漏 | 指出具体支持边及可行修法，不能只贴谬误名 |
| 一致性 | 定义、缩写、时间、空间单位、样本数、假设编号、方向、前后主张 | 联查对应位置，区分不同样本/窗口造成的合理差异 |
| 中文基础 | 错别字、成分残缺、搭配不当、句式杂糅、歧义、冗长、标点 | 给具体改法；长句不天然有错，以负担和歧义为依据 |
| 英文基础 | spelling、冠词、数、时态、主谓一致、修饰范围、指代、搭配、平行结构、标点 | 保留学科术语与英/美拼写体系，按语境修改 |
| 表达与叙述 | 空泛主体、弱动词、名词堆叠、重复、转折失配、段落任务不明 | 不提高证据强度；可选风格偏好明确标为可选 |
| 投稿形式 | 摘要/章节/字数/声明等 | 以对应期刊类型的现行官方要求为准，经验写法标明来源 |

严重度按影响判断：关键（动摇中心结论/主要数据解释）、主要（局部结论或可复现性）、次要（明确语言/符号错误）、可选（多个写法都成立）。不以某个词本身自动判错，不默认被动语态、长句或重复术语需要删除。

## 文件操作与验证

1. 先保存源文件哈希和段落清单；明确包含正文、表格、图注、脚注、文本框、补充材料的哪些范围。逐段审读，保留覆盖台账；脚本可写批注的范围不等于已经完成内容审查。
2. 用`python -X utf8 scripts/word_comments.py inventory input.docx inventory.json`生成稳定段落号。批注plan记录`paragraph`（从0起）、`quote`、`occurrence`（同段重复从1起）、`text`；使用`apply input.docx plan.json output.docx`。脚本先核对plan的`source_sha256`，批注前后正文字符必须一致。
3. plan顶层是`source_sha256`和`comments`数组，每项还可设`author`。角色和修改意见都写在`text`。同段多批注和重叠范围可用，定位不得跨段；跨段关系分开定位并互引。
4. 脚本保留压缩包其他成员，现有批注追加且ID去重。精确字符锚点目前支持普通文字run；遇到字段、超链接、修订、复杂对象或正文之外的内容，会拒绝该定位而不破坏文档。将这类位置转交可用的Word原生批注工具或专门OOXML处理，随后重验；不得跳过后宣称全文批注完成。脚注、页眉页脚、嵌套文本框属于另行处理范围。
5. 用`verify output.docx`核对批注正文、起止/引用标记、关系和内容类型；另检查原有批注和图表未丢失。渲染并查看所有页，复杂稿件对照原稿；图像/PDF通常不显示批注，不能只靠渲染宣布批注有效。原生Word可用时检查批注面板。
6. 交付批注DOCX及简短优先修改顺序。台账记录检查范围、未核事实和未能写入的批注；不把完整率描述成逻辑诊断准确率。真实稿件未试用前，示例验证仅证明文件操作可用。
